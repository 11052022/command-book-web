# 国内访问加速方案调研（决定后实施）

> 背景：站点部署于 GitHub Pages（`https://11052022.github.io/command-book-web/`），
> GitHub Pages 的 CDN 节点基本都在境外，国内用户访问偏慢、偶发不稳定。
> 本文记录所有候选方案的原理、成本、效果与操作方式，供后续决策使用。
> 状态：**调研完成，未实施（决策待定）** — 2026-09-12

---

## 问题本质

- GitHub Pages 的边缘节点（Fastly 等）在境内无落地节点，每次请求要跨境过墙；
- 造成：首屏慢（几秒~十几秒）、高峰期偶发超时/打不开；
- 对国内普通用户（手机为主）体感影响明显。

加速思路：**让流量在离用户更近的地方落地**（国内节点 / 更优的边缘网络）。
方案按"成本低 → 高"排列如下。

## 方案细化

### 方案 1：换 Vercel / Cloudflare Pages（推荐优先尝试）

- **原理**：从 GitHub 仓库一键导入，平台自动监听 push 构建部署，边缘网络比 github.io 国内可达性更好。
- **优点**：免费；几乎零改造成本；自动 HTTPS；以后连 deploy.bat 的 GitHub 推送环节都不用手动管（Vercel/CF Pages 都监听 GitHub push 自动部署）。
- **局限**：仍是境外节点，提升明显但不根治；国内访问体感取决于当地网络到对应节点的质量（晚上/高峰仍可能波动）。
- **操作**：
  - Vercel：`vercel.com` 用 GitHub 账号登录 → New Project → Import 仓库 `command-book-web` → 保持默认（框架会自动识别为纯静态）→ Deploy。
  - Cloudflare Pages：`dash.cloudflare.com` → Workers & Pages → Create → 连接 GitHub 仓库。
- **提示**：本项目是纯静态 + hash 路由，两者均零配置适配。
- **决策点**：Vercel（可达性更好，推荐）或 CF Pages（免费流量更高）二选一。

### 方案 2：Cloudflare Worker 反代 + 缓存（免费的中等收益方案）

- **原理**：写一个 Cloudflare Worker，把 `https://11052022.github.io/command-book-web/` 作为源站反代，并开启边缘缓存（静态资源全部可缓存，命中即不出境）。
- **优点**：免费；域名变成 `你的worker子域.workers.dev`，国内可达性中等提升；可开启 Cloudflare 缓存以大幅减少跨境请求。
- **局限**：需要写几十行 Worker 代码并发布；`.workers.dev` 在国内偶发被墙/DNS 污染风险（不稳）；比方案 1 复杂。
- **操作**：Cloudflare → Workers & Pages → 新建 Worker → 粘贴反代+缓存逻辑（给静态资源设 Cache-Control 并缓存）→ 发布。
- **备注**：这个方案的加速主要来自"缓存命中后不再跨境"，冷启动（首次访问）仍慢。

### 方案 3：jsDelivr 分流静态资源（零成本临时补丁）

- **原理**：GitHub 仓库中的文件可通过 `https://cdn.jsdelivr.net/gh/11052022/command-book-web@main/...` 访问，jsDelivr 在国内有节点；把页面里的 JS/CSS 资源改从 jsDelivr 加载，`index.html` 入口仍留在 github.io。
- **优点**：免费零成本；不改平台，老链接继续可用；大文件（shiki、JS 数据包）走国内节点后下载明显变快。
- **局限**：HTML 入口仍在境外，首屏的第一跳仍慢；由于本项目是"多 chunk 懒加载"，改资源路径需要调整构建配置（`base` 与资源 URL 前缀）并重新打包；jsDelivr 缓存刷新有延迟（发布新版本后资源可能滞后）。
- **适用**：暂时不换平台时的过渡手段。
- **注意**：本项目构建产物文件名都带 hash（`index-*.js`），理论上可安全引用 jsDelivr，但需要验证 hash 路径与发布节奏的配合。

### 方案 4：国内 CDN 回源 github.io（真·提速，需备案）

- **原理**：在腾讯云/阿里云/又拍云开通 CDN，把"源站"配成 `11052022.github.io`，用户请求走国内 CDN 节点，节点回源一次后缓存，后续均命中国内缓存。
- **成本**：按流量计费，静态页体积小，个人站约几元~几十元/月；又拍云有免费额度（需品牌使用说明）。
- **硬门槛**：**CDN 加速域名必须已备案**（国内 CDN 强制）。没有备案域名则此路不通。
- **效果**：高。国内访问体验接近国内托管的站点。
- **操作**：买域名 → 备案（约 1~2 周）→ 域名解析至 CDN → 配置源站为 github.io → 上线。
- **注意**：缓存的自动失效需依赖资源 hash（本项目已满足）；入口 HTML 建议短缓存/必回源保证更新可见。

### 方案 5：彻底国内托管（终极方案）

- **原理**：把站点搬到国内静态托管：腾讯云 COS / 阿里云 OSS 的静态网站托管 + 同厂商 CDN；或用国内对象存储 + 备案域名直接对外。
- **成本**：与方案 4 相当（几元~几十元/月按量），同样**需备案域名**。
- **效果**：最高，国内访问质量等于国内产品。
- **操作**：迁移构建产物上传 → 配 CDN → 备案域名接入；部署流程要换（不再依赖 GitHub Actions 或另配 CI）。
- **备注**：工程改造量最大（部署链路重写），是最后一步才考虑的方案。

## 我的建议（记录，供你决策）

1. **优先做方案 1（Vercel 导入）**：今天就能落地、免费、效果最明显的性价比选项；不满意再降级或叠加。
2. **方案 3 作为临时补丁**：若不换平台又想临时改善大文件加载，可以加做。
3. **方案 2 有 `.workers.dev` 稳定性风险**，不优先。
4. **方案 4/5 才是"真正快"**：前提是你有一个**已备案的国内域名**（硬门槛）。没有的话先放着，以后有域名再迁。
